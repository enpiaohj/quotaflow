# QuotaFlow 显示模式开发提示词

> 文档日期：2026-08-28  
> 文档版本：v1.0  
> 产品名称：QuotaFlow  
> 目标平台：Windows 11  
> 技术基线：.NET 8、WPF、MVVM

## 1. 任务背景

QuotaFlow 的四平台额度查询功能已经完成，托盘面板模式及以下托盘交互正在开发或已经存在：

- 单击托盘图标：打开/关闭面板；
- 双击托盘图标：打开并立即刷新；
- 中键：刷新全部平台；
- 右键：刷新、设置、开机启动、退出；
- `Esc`：关闭托盘面板；
- 点击面板外部：自动收起；
- 支持固定面板，固定后点击外部不关闭。

本轮不要重新开发额度查询，不要重构 Provider，不要重复实现上述托盘交互。本轮只在现有工程上新增并完善 **显示模式系统**。

核心目标：

> QuotaFlow 既能作为临时打开的托盘面板，也能变成可拖动的悬浮窗口或长期放在桌面的额度看板，并且三种模式之间切换自然、状态明确、不会互相冲突。

---

## 2. 开工前检查

1. 阅读当前仓库中的 `AGENTS.md`、`CLAUDE.md`、README 和现有设计文档。
2. 检查 Git 状态，保留用户已有修改，不覆盖正在开发的托盘交互。
3. 梳理当前窗口创建、托盘事件、外部点击检测、关闭/隐藏、置顶和配置保存的数据流。
4. 先画出当前窗口生命周期，再实施显示模式，不要直接在现有事件处理器中堆布尔判断。
5. 优先复用现有 Window、ViewModel、设置服务和托盘服务；只有现有结构无法安全支持模式切换时才做最小重构。
6. 若现有工程技术栈或命名与本文示例不同，以项目真实结构为准，但行为要求不得降低。

## 3. 本轮显示模式

建立三种明确的窗口显示模式：

```csharp
public enum WindowPresentationMode
{
    TrayPopup,
    Floating,
    DesktopPanel
}
```

不要使用多个互相矛盾的布尔值推断当前模式。模式是窗口行为的主状态，置顶、位置锁定、布局密度和透明度是独立属性。

### 3.1 托盘面板模式 `TrayPopup`

这是现有默认模式，保持既有行为：

- 从系统托盘附近打开；
- 不允许自由拖动；
- 不保存自由窗口坐标；
- 点击外部自动收起；
- `Esc` 收起；
- 不在任务栏显示；
- 下次打开重新定位到当前托盘图标/任务栏工作区附近；
- 托盘在屏幕上下左右任一边时均能正确定位；
- 面板不得超出当前显示器工作区。

本轮只做与其他模式切换所需的最小接入，不改变已经确认的托盘交互语义。

### 3.2 悬浮窗口模式 `Floating`

用于工作期间持续观察额度：

- 从托盘模式点击“图钉/悬浮”按钮进入；
- 窗口脱离托盘锚点；
- 支持通过标题区域拖动；
- 点击窗口外部不关闭；
- `Esc` 不关闭窗口；
- 保存窗口位置、尺寸和所在显示器；
- 支持“始终置顶”；
- 支持“锁定位置”；
- 支持标准/紧凑布局；
- 支持背景材质和透明度；
- 默认不在任务栏显示，仍通过托盘管理；
- 关闭按钮应隐藏窗口或返回托盘，不得直接结束后台应用。

从悬浮模式取消图钉时：

- 切回 `TrayPopup`；
- 清除自由窗口定位的当前应用状态，但可以保留悬浮模式上次位置用于以后再次进入；
- 窗口重新定位到托盘附近；
- 恢复托盘模式的外部点击和 `Esc` 行为。

### 3.3 桌面看板模式 `DesktopPanel`

用于长期放置在桌面角落：

- 默认采用紧凑布局；
- 默认不置顶，避免遮挡其他工作窗口；
- 支持拖动和位置锁定；
- 支持较高背景透明度，但文字、图标和进度条保持清晰；
- 默认隐藏次要操作，鼠标移入后显示工具栏；
- 点击外部不关闭；
- `Esc` 不关闭；
- 保存位置、尺寸、显示器、透明度和布局密度；
- 可设置启动后恢复桌面看板模式；
- 仍保留托盘图标和托盘右键入口；
- 不使用 Windows Widget、WebView 或网页容器模拟桌面组件。

桌面看板模式不是“鼠标穿透窗口”。本轮不实现鼠标穿透。

## 4. 独立窗口属性

模式之外至少建立以下独立状态：

```csharp
public sealed class WindowDisplaySettings
{
    public WindowPresentationMode Mode { get; set; }
    public bool IsAlwaysOnTop { get; set; }
    public bool IsPositionLocked { get; set; }
    public bool IsCompactLayout { get; set; }
    public double Opacity { get; set; }
    public WindowMaterial Material { get; set; }
    public SavedWindowPlacement? FloatingPlacement { get; set; }
    public SavedWindowPlacement? DesktopPlacement { get; set; }
}
```

### 4.1 置顶与位置锁定必须分开

- **始终置顶**：决定窗口是否位于普通窗口之上；
- **锁定位置**：决定窗口能否被拖动；
- 置顶但未锁定：可以拖动；
- 锁定但未置顶：固定在桌面某处，但其他窗口可以覆盖；
- 同时开启：固定悬浮监控；
- 同时关闭：普通自由窗口。

UI 和代码中不得继续使用含义模糊的单一“固定”状态代替这两个概念。

### 4.2 推荐默认值

| 属性 | 托盘面板 | 悬浮窗口 | 桌面看板 |
|---|---:|---:|---:|
| 点击外部收起 | 是 | 否 | 否 |
| `Esc` 收起 | 是 | 否 | 否 |
| 可拖动 | 否 | 是 | 未锁定时 |
| 保存位置 | 否 | 是 | 是 |
| 始终置顶 | 是 | 可配置，默认是 | 可配置，默认否 |
| 紧凑布局 | 可选，默认否 | 可选，默认否 | 默认是 |
| 默认透明度 | 100% | 95% | 85% |
| 操作栏 | 始终显示 | 始终显示 | 鼠标移入显示 |

## 5. 模式切换规则

允许以下切换：

```text
TrayPopup ⇄ Floating ⇄ DesktopPanel
```

不建议从托盘面板直接无状态跳入桌面看板；UI 可以提供入口，但内部仍须执行完整状态迁移。

模式切换必须集中由一个协调器管理，例如：

```csharp
IWindowPresentationCoordinator
- EnterTrayPopupAsync()
- EnterFloatingAsync()
- EnterDesktopPanelAsync()
- RestoreLastModeAsync()
```

协调器负责：

1. 解除上一模式事件订阅；
2. 保存上一模式窗口状态；
3. 设置窗口样式、置顶、任务栏可见性和外部点击策略；
4. 恢复目标模式的位置、尺寸、透明度和布局；
5. 更新 ViewModel 和图标选中状态；
6. 防止快速连续点击造成重入或状态错乱。

切换过程中不要销毁 Provider 状态或清空额度卡片，不要触发不必要的重新查询。

## 6. 拖动与位置锁定

### 6.1 可拖动区域

只允许以下区域触发拖动：

- 顶部标题栏的空白区域；
- 专用拖动手柄；
- 桌面看板模式下鼠标移入后出现的标题区域。

以下元素不得触发拖动：

- 刷新按钮；
- 图钉、置顶、锁定、模式切换按钮；
- 平台卡片中的交互元素；
- 进度条；
- 设置菜单。

优先使用 WPF/Win32 正确的窗口拖动机制，不要用持续修改 `Left/Top` 的低质量鼠标事件模拟。

### 6.2 边缘吸附

- 距离屏幕工作区边缘 12～16 DIP 时吸附；
- 支持左、右、上、下和四个角；
- 按住 `Shift` 拖动时临时关闭吸附；
- 吸附只作用于当前显示器工作区，不覆盖任务栏；
- 不要强制改变窗口尺寸；
- 吸附反馈应轻量，不播放声音。

### 6.3 位置锁定

- 锁定后禁止拖动；
- 锁图标显示明确选中状态；
- Tooltip 显示“位置已锁定”；
- 托盘右键菜单或窗口工具栏必须保留“解锁位置”；
- 锁定不能阻止模式切换、刷新或打开设置。

## 7. 多显示器、DPI 与位置恢复

必须正确支持 Windows 11 多显示器环境：

- 每显示器 DPI 感知；
- 100%、125%、150%、175%、200% 缩放；
- 不同缩放比例显示器之间拖动；
- 主副屏左右、上下排列；
- 任务栏位于不同边缘；
- 显示器断开、分辨率变化、远程桌面连接和休眠唤醒。

保存位置时不要只保存裸像素坐标。至少保存：

```csharp
SavedWindowPlacement
- MonitorDeviceName
- LeftDip
- TopDip
- WidthDip
- HeightDip
- SavedDpiX
- SavedDpiY
- LastUpdatedAt
```

恢复时：

1. 优先恢复到原显示器；
2. 原显示器不存在时转移到主显示器；
3. 将窗口限制在当前工作区内；
4. 至少保留标题栏/操作区完全可见；
5. 提供“恢复默认窗口位置”；
6. 不得因为旧坐标导致窗口永远出现在屏幕外。

---

## 8. 透明度与 Windows 11 材质

透明分为两类，不要混为一谈。

### 8.1 背景材质

支持：

- 跟随系统；
- Mica；
- Mica Alt；
- Acrylic；
- 纯色背景（兼容/降级）。

推荐：

- 托盘面板：Acrylic 或现有样式；
- 悬浮窗口：Mica Alt；
- 桌面看板：Acrylic；
- 系统不支持、远程桌面或高对比度模式下自动降级为纯色。

必须检测真实系统能力，不能仅设置半透明颜色冒充 Mica/Acrylic。

### 8.2 整体透明度

- 用户可在 70%～100% 之间调节；
- 建议提供 70%、80%、85%、90%、95%、100% 预设；
- 不允许低于 70%；
- 拖动滑块时实时预览；
- 鼠标移入桌面看板时可以临时增强到 100%，移开后恢复用户值；
- 透明度变化不能降低文字对比度到不可读；
- Windows 高对比度模式下强制关闭透明。

优先调整背景层透明度。若使用整个 Window 的 `Opacity`，必须验证文字、图标、阴影和子窗口不会一起变得模糊难读。

## 9. 标准与紧凑布局

### 9.1 标准布局

保留完整卡片信息：

- 平台名称和图标；
- 5 小时/7 天等额度窗口；
- 剩余百分比；
- 进度条；
- 重置倒计时；
- 最近更新时间；
- 单平台刷新和状态提示。

### 9.2 紧凑布局

目标是在桌面角落一眼看清：

```text
Claude    5h 82% · 7d 46%
Codex     5h 61% · 7d 73%
MiniMax   5h 58% · 7d 40%
DeepSeek  ¥48.91
```

要求：

- 不改变真实数据模型，仅改变视图呈现；
- 默认宽度约 300～340 DIP；
- 四个平台尽量无需滚动；
- 低额度仍使用橙色/红色并配合文字或图标；
- 未知数据不得显示为 0；
- 长平台名、不同币种和额外额度窗口不能破坏布局；
- 标准/紧凑切换后保存各模式尺寸；
- 桌面看板首次进入默认紧凑布局，用户可改回标准。

## 10. UI 控件与入口

### 10.1 窗口顶部工具栏

悬浮模式建议：

```text
QuotaFlow                  [图钉] [置顶] [锁定] [更多]
```

桌面看板：

- 默认弱化或隐藏工具栏；
- 鼠标移入窗口后淡入；
- 鼠标移开延迟约 500～800ms 淡出，防止闪烁；
- 锁定状态下仍能通过工具栏或托盘菜单解锁。

所有纯图标按钮必须有 Tooltip、键盘焦点和可访问名称。

### 10.2 设置页新增“显示与窗口”

只增加与本轮有关的设置：

```text
显示与窗口

默认显示模式
  托盘面板 / 悬浮窗口 / 桌面看板

窗口行为
  始终置顶
  锁定位置
  吸附屏幕边缘
  启动后恢复上次模式

显示样式
  标准 / 紧凑
  跟随系统 / Mica / Mica Alt / Acrylic / 纯色
  透明度 70%～100%
  鼠标移入时增强可读性

  [恢复默认窗口位置]
```

设置变更应实时预览；保存失败时恢复上一有效值并提示，不得让窗口进入不可操作状态。

## 11. 配置持久化

- 显示设置保存到现有非敏感配置服务；
- 不把显示设置和 OAuth/API Key 存到同一敏感文件；
- 写入采用原子替换，避免应用崩溃产生半截 JSON；
- 配置字段提供默认值和版本迁移；
- 新版本遇到未知枚举值时安全回退到 `TrayPopup`；
- 高频拖动过程中不要每个像素都写磁盘，使用防抖，在拖动结束或短暂空闲后保存；
- 应用正常退出、Windows 注销和系统关闭时尝试保存最终位置。

---

## 12. 动画与视觉要求

- 模式切换采用 120～200ms 的轻量淡入/位移动画；
- 不使用弹跳、过度缩放或长动画；
- 刷新数据不能触发整个窗口重新出现动画；
- 窗口拖动期间禁用昂贵的阴影/模糊动画，保证流畅；
- 跟随 Windows“减少动画”设置；
- 跟随浅色、深色和高对比度模式；
- 圆角、阴影和边框与现有 QuotaFlow 视觉统一；
- 不因为透明材质牺牲额度数字的可读性。

---

## 13. 键盘与可访问性

- `Esc` 只在托盘面板模式收起窗口；
- 悬浮/桌面看板中的 `Esc` 可用于关闭菜单或取消操作，但不隐藏主窗口；
- 所有工具栏按钮支持键盘访问；
- 焦点顺序符合视觉顺序；
- 锁定、置顶和当前模式不能只依赖颜色表达；
- 屏幕阅读器能读出“当前模式、是否置顶、是否锁定、透明度”；
- 高对比度模式自动使用不透明背景和系统色。

如已有全局快捷键，不要擅自覆盖。若项目尚无全局快捷键，本轮不新增复杂快捷键系统。

---

## 14. 本轮明确不做

- 鼠标穿透；
- Windows 原生 Widget；
- 多个独立平台悬浮卡片；
- 自由卡片排序；
- 任意窗口皮肤；
- 桌面边缘自动隐藏；
- 跨设备同步窗口配置；
- 新 Provider；
- 历史趋势和图表；
- 额度通知系统；
- 重写托盘交互；
- 重写平台查询功能。

如果发现现有代码中的阻塞性问题，只做本轮所需的最小修复，并在报告中说明。

## 15. 建议实施顺序

1. 梳理现有窗口生命周期和托盘行为；
2. 建立 `WindowPresentationMode` 和显示设置模型；
3. 建立统一的模式切换协调器；
4. 接入现有 `TrayPopup`；
5. 实现 `Floating` 模式；
6. 实现拖动、位置保存、置顶和位置锁定；
7. 实现多显示器/DPI 恢复和屏外兜底；
8. 实现 `DesktopPanel`；
9. 实现标准/紧凑布局；
10. 实现 Mica/Acrylic/纯色降级；
11. 实现透明度和鼠标移入增强；
12. 完善设置页、可访问性和自动化测试；
13. 在 Windows 11 真机完成手工验证；
14. Release 构建、备份并输出报告。

不要为了尽快看到界面跳过状态机、多显示器和配置恢复；这些是显示模式能否长期稳定使用的关键。

## 16. 测试要求

至少覆盖以下测试：

### 16.1 状态与模式

- 三种模式切换正确；
- 快速连续切换不重入；
- 切换模式不清空额度数据；
- 切换模式不重复创建 Window 或托盘图标；
- 应用重启后按设置恢复模式；
- 配置损坏时回退到托盘模式。

### 16.2 交互

- 托盘模式外部点击和 `Esc` 仍然有效；
- 悬浮/桌面模式外部点击不会关闭；
- 悬浮/桌面模式按 `Esc` 不隐藏主窗口；
- 锁定后不能拖动，解锁后恢复；
- 置顶和位置锁定互不影响；
- 标题栏按钮点击不会误触发拖动；
- 模式切换期间刷新仍能安全完成。

### 16.3 显示器与 DPI

- 100%、125%、150%、200% 缩放；
- 不同 DPI 显示器之间移动；
- 副屏断开后窗口回到主屏；
- 分辨率变化后窗口仍可见；
- 任务栏在四个方向时托盘模式正确定位；
- 远程桌面连接/断开后位置可恢复。

### 16.4 视觉与配置

- 浅色、深色、高对比度；
- 材质不支持时纯色降级；
- 70%～100% 透明度边界；
- 紧凑布局四平台不重叠；
- 设置写入防抖和原子保存；
- 恢复默认位置有效。

优先将模式状态机、位置修正算法和配置迁移写成可单元测试的纯逻辑，不要所有测试都依赖 UI 自动化。

---

## 17. 验收标准

以下条件全部满足才算完成：

1. 现有托盘交互没有回归；
2. 三种模式可以稳定切换；
3. 悬浮窗口可以拖动、置顶和锁定；
4. 桌面看板适合长期放置，不会因点击外部消失；
